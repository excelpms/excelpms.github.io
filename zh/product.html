产品详解 / 完整项目管理架构

一套架构，连接项目工作。
从计划一直到管理报告。

Project Control 组织整体项目，文件模块管理工程交付与往来，执行数据经规则计算与加权汇总，进入看板、前瞻和报告。下面按这条主线展开各模块的能力与关系。

01 / 项目计划与逻辑排程

设计、采购、制造，放进同一套 WBS。

Project Control 是整体项目计划与进度的组织框架。建立 WBS 层级、Task ID 和任务权重，用任务之间的前置关系连接各阶段工作，安排普通任务与工程文件相关任务。

  • 支持 FS、SS、FF、SF，多前置关系及正负 Lag。
  • 结合工作日历，使用 D 工作日或 ED 日历日工期，进行手工与自动排程。
  • 按层级汇总，生成按天展示的静态甘特图；普通叶任务支持零工期里程碑。
从一组日期，走向有结构、有依赖、有汇总依据的项目计划。

02 / Baseline 与 Re-schedule

保留基准，也给调整后的计划一个位置。

Baseline 与 Re-schedule 分别维护日期、工期、工期单位和前置关系。实际执行数据独立管理，便于按选定口径比较计划与实际。

  • 两套计划可分别显示和修改，保留各自的排程数据。
  • 切换显示、修改计划、发布文件计划是不同操作，按需要分别完成。
  • 报告选择对应 Basis，让计划比较、曲线与报告说明采用一致口径。
计划发生变化时，仍能区分原有安排、调整安排和真实执行。

03 / VDR Planner 工程文件计划

把工程交付节点，接到后续项目工作。

VDR Planner 规划文件首次提交、审查与重提周期、各轮目标 Code 和计划进度。工程文件节点可作为采购、制造等后续任务排程的依据。

  • 使用 Vendor / Client 工作日历，结合文件依赖关系组织日期。
  • 规划审查轮次、目标 Code 和各节点计划进度。
  • 向 VDR 和 Project Control 单向发布到指定的 Baseline 或 Re-schedule，调整后按流程重新发布。
文件计划成为总体项目计划的一部分，体现工程审查对后续工作的影响。

04 / VDR · GDR · Transmittal

工程交付与日常往来，记录清楚。

VDR 基于预设工程文件清单管理提交、客户回复、分供方来文、版本与审查 Code。GDR 管理 TQ、CRS、NCR、MOM 等事件型文件、回复和附件，无需预建工程文件清单。

  • 按可配置规则识别 Doc No. 与 Revision，归档并更新登记和链接。
  • 生成自定义传送单及 PDF，配套传送单登记。
  • 相关业务操作有对应撤销流程，便于按规定处理更正。
文件处理、往来台账和交付依据相互关联，减少重复整理。

05 / 实际进度与历史数据

任务与文件进度，汇入整体项目。

采购、制造等普通任务维护实际日期和进度；工程文件按文件类型、First Issue、First Return 及审查 Code 规则计量。两类数据经 WBS 权重汇总，形成项目实际进度。

  • 自定义文件进度比例与行为，按类型选择是否按 Planner 计划轮次计取中间进度。
  • Record Actual Progress 记录当前报告期实际进度。
  • Refresh Actual Progress 依据文件历史与规则重算历史数据，处理补录和修正等情况。
既看当前完成情况，也能维护有依据的历史进度。

06 / Dashboard 与 Lookahead

看板看全局，前瞻抓行动。

Dashboard 呈现总体、专业与类别状态及偏差；Lookahead 根据时间窗口聚焦近期、逾期和落后工作。汇总结果进一步指向需要协调和推动的事项。

  • 按参考日期、任务范围、事项类型和计划口径查询。
  • 识别未按时开始、已逾期、待提交或待回复等关注项。
  • 从查询结果定位 Project Control 或 VDR 源记录，便于核实和追问。
从“项目怎么样”，走到“接下来要推动什么”。

07 / 进度曲线与周期报告

日常数据，延续到每一期管理报告。

组织 Baseline、Re-schedule 和 Actual 曲线、分期进度与管理报告。日、周、双周、月末或固定月度日期等周期按项目配置。

  • 按 WBS、时间范围和计划口径组织曲线数据。
  • 按工作流程记录实际、刷新曲线和报告内容。
  • 结合数据、曲线与管理说明形成报告，并通过 Excel 导出 PDF。
减少每期重新拼表，让计划、实际和报告口径相互衔接。

PMS V1.0 / PROJECT WORK IN PRACTICE

项目会变化，管理也能跟上。

MILESTONES / 项目里程碑

关键节点，也进入项目计划。

普通叶子任务可用数字 0 工期表示项目启动、订单生效或交付确认等里程碑，与前置任务、双计划和甘特图衔接。

  • Baseline 与 Re-schedule 分别维护节点日期和关系，甘特图用菱形标识。
  • 计划到期与实际达成分别记录；节点可按项目计量约定设置权重。
VDR MAINTENANCE / 执行中清单维护

改号、新增、取消，保留业务来龙去脉。

执行中的项目可在统一维护页修改文件号或标题、增加文件、取消文件；先检查整批变更，再确认执行。

  • 编号和标题变更关联 VDR、Planner、PC 与登记记录，历史编号可参与旧编号来文识别。
  • 已发生的历史往来与已发传送单保留；维护后核对计划、权重和当期进度。
REVIEW STATUS / 审批状态与行动

审批走到哪一步，进度完成了多少，分别看清。

看板可对比计划与实际的文件提交、待审及审批分类；审查 Code 的状态分类按项目含义配置，与进度计取规则分别维护。

  • 审批状态与完成百分比表达不同信息，避免用一个数字代替全部项目状态。
  • 待提交、待重提与待回复等关注项支持后续协调和推动。
SETTINGS / PROJECT RULES

项目自己的规则，进入日常工作。

按项目配置 WBS、任务权重、Vendor / Client 工作日历、文件类型、审查 Code、进度计取、文件名识别、传送单与报告周期。保留 Excel 的熟悉操作，由 VBA 承担重复处理，用户按流程完成必要的配置、确认与刷新。
